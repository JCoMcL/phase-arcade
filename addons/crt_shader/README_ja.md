# CRT Shader for Godot

[English](README.md) | 日本語

Godot 4 用の2段構成 NTSC/CRT テレビシェーダーです。ドロップインで使える
`CRTScreen` ノードとして提供します。

![CRTシェーダーのデモ](docs/images/thumbnail.png)

- **CRTモニタの表現結果を真似たシミュレータではありません。** 実際にCRTのRF信号を
  作成して受信し、ビームをRGBマスクに当てて発光させます。各種の劣化は、その過程から
  副産物として現れるものであり、後付けのエフェクトではありません。
- **RGBマスクは色の並び方を選択できます**。スロットマスク／アパーチャーグリル／
  シャドウマスクの3方式。
- **RF受信時の信号劣化を再現可能です**。RF離調、カラーバースト位相揺れ、水平同期揺れ、
  ゴースト、スノー、AGC揺れを、1本のマスター量でまとめて調節できます。
- **ビームの僅かなズレと曲がり方を調節する**ことで（コンバージェンス誤差と管面カーブ）、
  実際のモニタと同じ偽色が発生します。
- **偶数ラインと奇数ラインを交互に描画するインターレースに対応**しています。
- **縦画面ゲームでは、実際のモニタを回転したようにプレーンを回転**させます。走査線と
  蛍光体マスクも管面と一緒に回ります。
- **特殊なパラメータ調整をしない限り、通常はフレーム落ちがありません。** 重いStage1の
  フィルタは表示解像度ではなく信号解像度で走るためです。
- **48個のパラメータ**を1つの `CRTSettings` リソースにまとめ、**5種のプリセット**と
  JSON入出力に対応。自作の設定画面へも組み込めます。
- エディタ上でも動作します。`CRTSettings` を割り当てれば、スライダー操作がそのまま
  ビューポートに反映されます。

[TurnTV](https://github.com/TSUISHI/TurnTV) の CRT エミュレータを取り出し、
再利用可能な Godot アドオンとして再構成したものです。

## 仕組み

多くのCRTフィルタは、出来上がった絵の上に走査線とマスクを描き足すだけの
シミュレータです。このシェーダーは違います。CRTの仕組みそのものを再現し、
劣化は「その結果として」現れます。

1. 映像をYIQへ変換し、**NTSCカラーサブキャリアへ変調**します。実際にコンポジット
   信号を作ります。
2. その信号を**RF受信時と同じように劣化**させます。不完全なY/C分離、Y/I/Qの帯域制限、
   RF離調、カラーバースト位相揺れ、水平同期PLLの追従残差、ゴースト、スノー、AGC揺れ。
3. そして**復調**します。虹色の偽色・ドットクロール・色にじみは、この往復で
   取り切れなかった残りであって、後から描き足したエフェクトではありません。
4. 復元した映像を、**ビームでRGB蛍光体マスクに当てて発光**させます。ビームは明るさに
   応じて太くなり、蛍光体の並び方（スロットマスク／アパーチャーグリル／シャドウマスク）
   を選べます。
5. ビームの僅かなズレと曲がり——コンバージェンス誤差と管面カーブ——を調節することで、
   実際のモニタと同じ色付きの輪郭が発生します。
6. **インターレース**に対応し、偶数ラインと奇数ラインをフィールドごとに交互に描画します。
7. 縦画面ゲームでは、実際のモニタを横倒しにするのと同じように、プレーンごと回転します
   （[縦画面（タテ）ゲーム](#縦画面タテゲーム)を参照）。

Stage1 はクロスカラー・クロスルミナンス、色ずれ、Y/I/Q の帯域制限、ドットクロール、
ゴースト、アナログノイズ、水平同期揺れ、RF離調、カラーバースト位相揺れ、RFスノー、
AGC揺れを扱います。Stage2 は輝度依存ビーム幅、蛍光体マスク、ガンマ、バレル歪み、
角丸、外周減光、ベゼル暗部、480i風表示、水平シャープネス、RGBコンバージェンス誤差、
ハレーションを扱います。

## 動作環境

- Godot 4.6 以降
- Forward+ / 互換性（Compatibility）どちらのレンダラーでも動作します。
  デモプロジェクトは古いGPUでも動くよう互換性レンダラーを使用しています。

## 導入

Godot の **アセットライブラリ** タブから導入するか、`addons/crt_shader` フォルダを
プロジェクトへコピーしてください。

プラグインの有効化は不要です。`CRTScreen` / `CRTSettings` / `CRTPresets` は
`class_name` で登録されるため、すぐに「ノードを作成」ダイアログへ `CRTScreen` が
現れます。フォルダは自己完結していて内部の参照もすべて相対パスなので、移動や
リネームをしても動作します（`addons/` の下に置く必要はありません）。

アセットライブラリからのダウンロードにはアドオン本体だけが含まれます。デモと
ドキュメントが必要な場合はリポジトリをクローンしてください。

## 使い方

### テクスチャを表示する

```gdscript
var crt := CRTScreen.new()
crt.set_anchors_preset(Control.PRESET_FULL_RECT)
crt.source_texture = preload("res://art/title.png")
add_child(crt)
```

### ゲーム画面をCRTに通す

`get_content_root()` の下に置いたものは信号解像度で描画され、2段のシェーダーを
通ります。

```gdscript
@onready var crt: CRTScreen = $CRTScreen

func _ready() -> void:
    crt.signal_resolution = Vector2i(320, 240)
    crt.get_content_root().add_child(preload("res://game/game.tscn").instantiate())
```

この方法で追加した内容はシーンファイルには保存されません。シーンに保存したい
場合は、自前の `SubViewport` で描画してそのテクスチャを渡してください。

```gdscript
crt.source_texture = $GameViewport.get_texture()
```

### 見た目を変える

```gdscript
crt.apply_preset(CRTPresets.FAMICOM_RF)   # プリセットごと適用
crt.set_param("scanline_strength", 0.55)  # 1パラメータだけ変更
```

インスペクタで調整する場合は、ノードの **Settings** プロパティに `CRTSettings`
リソースを新規作成して割り当ててください。全パラメータがグループ分けされて表示され、
操作すると画面へ即座に反映されます。`.tres` として保存すれば使い回せます。

## 縦画面（タテ）ゲーム

独立した2つの90度回転で、あらゆる配置に対応できます。

| プロパティ | 回るもの | 走査線 |
|---|---|---|
| `screen_rotation` | 管面全体（マスクと走査線を含む） | 管面と一緒に回る |
| `content_rotation` | 管面の中の映像だけ | 水平のまま |

昔ながらのタテ筐体は「横長の管面を横倒しにし、ゲームの絵を回して描く」構成です。
Godot では次のように書きます。

```gdscript
crt.screen_rotation = CRTScreen.Rotation.DEG_90   # 管面を横倒しにする
crt.content_rotation = CRTScreen.Rotation.DEG_270 # ゲームを正立させる
```

![タテ置きモード](docs/images/thumbnail_tate.png)

結果は**走査線と蛍光体マスクが縦向きになった**縦長の映像になります。
横置きCRTを縦に切り取ったものとは根本的に異なる、実機どおりの見え方です。

90度回転すると描画領域は転置されるため、320x240 の信号では
`get_content_size()` は 240x320 を返します。`content_size_changed` シグナルで
新しい形にレイアウトし直してください。ゲーム自体を最初から縦解像度で作っている
場合は、`signal_resolution` を縦サイズにして `screen_rotation` だけを使います。

コントロールの形が管面と違うときの挙動は `display_fit` で決まります。
`KEEP_ASPECT`（既定）は管面のアスペクトを保って中央に配置し、余白を
`letterbox_color` で塗ります。`STRETCH` はコントロール全体を覆います。
非正方ピクセルの場合は `screen_aspect` を明示してください（例: 256x224 の絵を
4:3 のテレビに映すなら `4.0 / 3.0`）。

## プリセット

| プリセット | 見た目 |
|---|---|
| `COMPOSITE_TV` | 既定値。コンポジット接続のテレビ |
| `CRT_STUDIO` | RF不安定を排した高画質モニタ。シャープでハレーション強め |
| `FAMICOM_RF` | アンテナ端子接続。偽色・スノー・同期揺れが強い |
| `RGB_DIRECT` | RGB/SCART接続。コンポジット劣化なしのCRT |
| `LIGHTWEIGHT` | 走査線とマスクのみ。低性能GPU向け |

プリセットは映像パラメータのみを変更し、記載のないパラメータは既定値へ戻ります。

## パラメータ

全48項目は [docs/PARAMETERS_ja.md](docs/PARAMETERS_ja.md) にまとめています
（英語版: [docs/PARAMETERS.md](docs/PARAMETERS.md)）。シェーダー本体のコメントには、
各パラメータの信号処理上の意味をさらに詳しく書いています。

## 負荷について

Stage1 の17タップFIRは**信号解像度**で走るため、ウィンドウが 640x480 でも 4K でも
コストは変わりません。Stage2 は表示ピクセルごとに走り、最大8回の追加テクスチャ
サンプル（ハレーション4・コンバージェンス2・シャープネス2）を行います。

低性能GPUではまず `LIGHTWEIGHT` から試してください。手動で削るなら次の順です。

1. `halation_strength` を 0（サンプル4回削減）
2. `convergence_x_px` と `convergence_y_px` を 0（2回削減）
3. `horizontal_sharpness` を 0（2回削減）
4. `signal_amount` を 0（17タップFIR自体をスキップ）
5. `signal_resolution` またはコントロールのサイズを小さくする

## デモ

Godot でプロジェクトを開いて実行してください。操作は次のとおりです。

| キー | 動作 |
|---|---|
| Tab / F1 | パラメータパネルの表示切替 |
| R / Shift+R | 管面を回転（タテ置き） |
| C | 内容を回転 |
| Space | アニメーション停止 |
| 1-5 | プリセット適用 |
| O | 画像ファイルを開く |
| P | テストパターンへ戻す |
| Esc | 終了 |

ウィンドウへ画像ファイルをドロップすると、その画像をCRT越しに表示します。
**JSONをコピー**ボタンで現在の設定をクリップボードへ書き出せます。

### デモの環境変数

スクリプトからスクリーンショットを撮るためのもので、通常利用では不要です。

| 変数 | 動作 |
|---|---|
| `CRTSHADER_SHOT=<PNGパス>` | スクリーンショットを保存して終了 |
| `CRTSHADER_SHOT_FRAME=<n>` | 撮影するフレーム番号（既定60） |
| `CRTSHADER_CLEAN=1` | UIを隠してキャプチャ |
| `CRTSHADER_SCREEN_ROTATION=<度>` | 管面を回転した状態で起動 |
| `CRTSHADER_CONTENT_ROTATION=<度>` | 内容を回転した状態で起動 |
| `CRTSHADER_LANG=en\|ja` | UI言語の上書き |

## クレジット

このシェーダーは制作中のレトロゲーム向けに書かれ、
[TurnTV](https://github.com/TSUISHI/TurnTV) で初めて公開したものです。
以下のプロジェクトの手法に着想を得た拡張を加えています。

- [ShaderGlass](https://github.com/mausimus/ShaderGlass) — プリセット運用、
  水平シャープネス、RGBコンバージェンス誤差、ハイライトのハレーション。
- [famicom-rf-hackrf-decoder](https://github.com/GOROman/famicom-rf-hackrf-decoder)
  — 水平同期PLLの追従残差、RF離調、カラーバースト位相不安定、AGC変動、RFスノー、
  復調後の色相・彩度調整。

実装はすべて独自に記述しており、参照プロジェクトのソースコードは複製していません。
